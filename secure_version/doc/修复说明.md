# secure_version 安全修复说明

本文档记录 `secure_version` 相比 `vulnerable_version` 的主要安全修复点。

## 1. SQL 注入修复

后端数据库访问已改为参数化查询。

修复方式：

- `fetch_one(sql, params)`
- `fetch_all(sql, params)`
- `execute_sql(sql, params)`
- 搜索、登录、注册、管理端 CRUD、志愿、录取分配等接口不再使用用户输入拼接 SQL。

## 2. 认证和权限修复

漏洞版依赖前端传入 `X-Role` 判断管理员权限，安全版改为服务端 token。

修复方式：

- 登录成功后后端签发带签名和过期时间的 token。
- 前端通过 `Authorization: Bearer <token>` 发送请求。
- 后端校验 token 签名和有效期后读取当前用户和角色。
- 管理端接口统一调用 `ensure_admin()`。
- 学生端接口统一调用 `ensure_student()` 或当前用户校验。

## 3. 明文密码修复

安全版不再保存明文密码。

修复方式：

- 使用 `hashlib.pbkdf2_hmac` 生成 `pbkdf2_sha256` 密码哈希。
- 登录时使用常量时间比较校验密码。
- 注册、管理员重置密码、用户修改密码均保存哈希。
- 启动时会将旧明文密码迁移为哈希。

## 4. IDOR 越权修复

漏洞版学生接口依赖前端传入 `user_id`，安全版改为从 token 识别当前用户。

修复方式：

- `/api/student/profile`
- `/api/student/score`
- `/api/student/admission`
- `/api/student/choices`

这些接口不再信任前端传入的 `user_id`，只操作当前登录学生自己的数据。

## 5. XSS 修复

漏洞版学生公告详情使用 `v-html` 渲染公告内容。

修复方式：

- 前端移除 `v-html`。
- 后端保存公告时对标题、内容、发布人做 HTML 转义。

## 6. CORS 收敛

漏洞版 CORS 允许任意来源。

修复方式：

- 只允许本地开发前端来源：
  - `http://127.0.0.1:5173`
  - `http://localhost:5173`
- 只开放必要请求头：
  - `Authorization`
  - `Content-Type`

## 7. 调试接口移除

漏洞版存在 `/api/debug/users`，会泄露账号和密码。

修复方式：

- 安全版删除该接口。
- 后端不提供返回密码字段的调试接口。

## 8. 输入校验增强

安全版使用 Pydantic 对主要输入增加约束。

包括：

- 学号、姓名、密码长度。
- 成绩范围。
- 招生计划年份和人数范围。
- 公告标题和内容长度。
- 部分枚举字段校验。

## 9. 学生端资源归属校验

志愿新增、编辑、删除、排序均绑定当前登录学生。

修复方式：

- 后端从 token 获取当前学生。
- `choice_id` 必须属于当前学生。
- 已录取或未录取后禁止修改志愿。

## 10. 录取分配安全约束

安全版录取分配不能任意修改已发布结果。

规则：

- 录取时必须选择该学生自己的志愿。
- `已发布` 且结果不是 `待定` 的录取记录不能再次修改。
- 录取分配是唯一更新最终录取状态的入口。

## 当前限制

安全版 token 已改为 HMAC-SHA256 签名的无状态 token，包含过期时间。只要 `ADMISSION_TOKEN_SECRET` 不变，后端重启不会导致所有登录态立即失效。

生产环境建议：

- 设置强随机 `ADMISSION_TOKEN_SECRET`，不要使用默认开发密钥。
- 配合 HTTPS，避免 token 在传输中泄露。
- 如果需要“退出登录后服务端立即吊销 token”，需要增加 token 黑名单或服务端 session 存储。
