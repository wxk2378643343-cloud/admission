# 高校招生录取系统漏洞清单（未防护版）

## 1. 文档说明
- 目标：给出当前系统可复现的安全漏洞，支撑论文“漏洞复现与修复方案”章节。
- 版本范围：当前 `backend/app/main.py` 与前端分离版（Vue）。
- 说明：本系统为教学与毕设演示用未防护版本，不可用于生产环境。

## 2. 漏洞总览
1. SQL 注入（登录接口）
2. 身份伪造/权限绕过（`user_id` 参数信任）
3. IDOR 对象级越权（档案详情接口）
4. Excel 导入 `eval` 执行风险
5. 明文密码存储
6. 登录缺少防爆破
7. CORS 过宽

---

## 3. 漏洞详情

### 3.1 SQL 注入（高危）
- 接口：`POST /api/login`
- 位置：`backend/app/main.py` 中登录 SQL 拼接
- 问题描述：用户名和密码直接拼接进 SQL 语句，未使用参数化查询。
- 影响：可绕过登录并获取任意角色身份。

复现示例（思路）：
1. 打开登录接口。
2. 在用户名或密码字段构造注入片段。
3. 观察是否在无真实凭据下返回登录成功。

修复建议：
- 全面改为 ORM 条件查询或参数化 SQL。
- 对登录失败做统一返回，避免泄露细节。

### 3.2 身份伪造/权限绕过（高危）
- 接口：多数业务接口（如 `/api/profiles`、`/api/admissions` 等）
- 位置：`get_current_user(user_id)` 及所有 `user_id` 查询参数鉴权链路
- 问题描述：后端直接信任客户端传入 `user_id` 识别登录身份。
- 影响：攻击者可篡改 `user_id` 冒充管理员，调用管理员接口。

复现示例（思路）：
1. 普通账号登录。
2. 抓包或手工构造请求，把 `user_id` 改为管理员 ID。
3. 请求管理员接口，观察是否成功执行。

修复建议：
- 使用 JWT 或服务端 Session。
- 后端从 Token/Session 中解析用户身份，禁止客户端直传身份主键。

### 3.3 IDOR 对象级越权（中高危）
- 接口：`GET /api/profile/{profile_id}`
- 位置：接口仅校验“已登录”，未校验“资源归属”。
- 问题描述：普通用户可通过修改 `profile_id` 查看他人档案。
- 影响：敏感信息泄露（身份证号、电话等）。

复现示例（思路）：
1. 使用考生账号访问自己的 `profile_id`。
2. 将路径参数改为其他考生 ID。
3. 观察是否返回他人档案数据。

修复建议：
- 增加归属校验：`profile.user_id == current_user.id`。
- 管理员与考生权限分支严格分离。

### 3.4 Excel 导入 `eval` 执行风险（高危）
- 接口：`POST /api/scores/import`
- 位置：`total_raw` 以 `=` 开头时调用 `eval(total_raw[1:])`
- 问题描述：导入内容中的表达式可在服务端执行。
- 影响：存在远程代码执行风险，严重威胁系统与主机安全。

复现示例（思路）：
1. 构造带表达式内容的导入模板。
2. 上传到成绩导入接口。
3. 观察异常执行行为或日志变化。

修复建议：
- 严禁 `eval`。
- 仅允许数值类型，非数值直接拒绝。
- 对导入字段做白名单与范围校验。

### 3.5 明文密码存储（高危）
- 位置：用户注册/创建时密码直接存储。
- 问题描述：数据库中保存原始密码。
- 影响：数据库泄露后造成批量账号失陷。

修复建议：
- 使用 `bcrypt` 或 `argon2` 哈希存储。
- 登录时进行哈希比对，不可逆恢复。

### 3.6 登录缺少防爆破（中危）
- 接口：`POST /api/login`
- 问题描述：无验证码、无频率限制、无失败锁定。
- 影响：可被暴力猜解或撞库。

修复建议：
- 增加限流（IP + 账号维度）。
- 连续失败锁定与验证码挑战。
- 增加登录审计日志。

### 3.7 CORS 过宽（中危）
- 位置：全局 CORS 配置 `allow_origins=["*"]`
- 问题描述：跨域来源过宽，放大攻击面。
- 影响：不受信任站点可更容易发起跨域交互。

修复建议：
- 生产环境仅允许受信任域名白名单。
- 开发与生产分环境配置。

## 4. 风险等级建议（论文可用）
- 高危：SQL 注入、身份伪造、`eval` 执行、明文密码
- 中高危：IDOR 越权
- 中危：暴力破解风险、CORS 过宽
